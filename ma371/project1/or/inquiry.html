Keeping a Fleet Ready

Guided inquiry and individual writing assignment

Work collaboratively in class; final writing is individual. Record your responses in the packet or your own notes. This web version includes conceptual explanations alongside the case and inquiry prompts.

The decision: a closed fleet has 100 vehicles: 30 ready, 40 in routine maintenance, and 30 in major repair. A training event is two weeks away. The planning criterion is at least 70 expected-ready vehicles at the end of week 2. Exactly one proposal can receive the same fictional one-time $20,000 budget: prevention reduces entry into maintenance from the ready state; faster repairs improves return-to-ready transitions.

Advise which proposal, if either, the evidence supports for this deadline. Explain whether a longer planning horizon could change the decision. All records and estimates are synthetic teaching data, not operational evidence.

50-minute plan: understand the case (8); construct the model (10); investigate with the calculator (12); challenge the evidence (12); prepare a claim and save work (8).

2. Translate the case into linear algebra

x→k+1 = A x→k   (3 × 1) = (3 × 3)(3 × 1)

For the baseline forecast, use A = A0 from Table 2. Its entry aij is the Table 1 count from origin j to destination i divided by the total for origin j. For example, a11 = 80/100 = 0.80 = 80%. Table 2 shows percentages for reading; enter the equivalent decimals, such as 0.80, when computing.

Why this is a discrete dynamical system

The state vector x→k records the fleet's ready, routine-maintenance, and major-repair counts at the end of week k, in that order. The initial vector x→0 contains actual starting counts; later vectors contain model-predicted expected counts.

  • Discrete: the model updates at separate weekly intervals, k = 0, 1, 2, …, rather than continuously.
  • Dynamical: the state changes over time. Multiplying the current state vector by A produces the next predicted state vector.
  • Linear: each group's expected contribution is proportional to its current size, and the contributions add. Matrix multiplication performs that weighted sum for each destination state.
  • Time-invariant: within each scenario, we assume the same transition matrix applies every week. If rates change from week to week, one fixed power Ak no longer describes the forecast.

We also assume transition probabilities depend on a vehicle's current state, not on its earlier history. For example, the model treats all vehicles currently in major repair alike, regardless of how long they have been there.

What one multiplication means

For the baseline, the full one-week update is

A0x→0 = x→1 = [5029.520.5].

The expected ready count is the first coordinate of that vector. The subscript outside the parentheses below selects this coordinate, which is a scalar rather than the whole state vector:

(x→1)1 = 0.80(30) + 0.50(40) + 0.20(30) = 50.

The three terms represent vehicles that remain ready, return from routine maintenance, and return from major repair, respectively. The second and third coordinates are found by using the second and third rows of A0 in the same way.

Fractional entries are expected counts, not fractional vehicles. Each column of A sums to 1 because every vehicle in that origin state must move to exactly one of the three destination states. Therefore, multiplication redistributes the fleet without changing its total size.

From one week to several weeks

x→1 = Ax→0,   x→2 = Ax→1 = A2x→0,   x→k = Akx→0.

Each multiplication advances the forecast one week. Here we are forecasting a changing state from a known starting state, not solving a single static system Ax→ = b→.

Why normalize the eigenvalue-1 eigenvector?

Eigenvectors do not have a unique scale: if Aq→ = q→, then A(cq→) = cq→ for any nonzero scalar c. Consequently, the eigenvalue equation alone does not tell us whether the coordinates represent proportions, vehicle counts, or another scaling.

For these matrices, choose a nonzero eigenvalue-1 eigenvector q→ with nonnegative coordinates. Divide by the sum of those coordinates:

p→ = q→q1+q2+q3,   p1 + p2 + p3 = 1.

This scaling preserves the eigenvector equation but makes the coordinates interpretable as fleet proportions. Here, normalized means the coordinates sum to 1; it does not mean the vector has Euclidean length 1.

For example, the baseline matrix satisfies A0q→ = q→ for q→ = [621]. Dividing by 9 gives proportions 6/9, 2/9, and 1/9. For a 100-vehicle fleet, 100p→ gives long-term expected counts of about 66.67 ready, 22.22 in routine maintenance, and 11.11 in major repair.

Here, A0 is the matrix of transition probabilities; q→ = (6, 2, 1)T is an eigenvector, not another transition matrix or a list of percentages. Only after dividing by 9 do its coordinates describe proportions.

Normalizing does not create equilibrium or make a model accurate. It selects a useful scale for an eigenvector that already satisfies the stationary equation.

Why eigenvalues help explain the forecast

If A has a basis of eigenvectors and x→0 = c1v→1 + c2v→2 + c3v→3, then

x→k = c1λ1kv→1 + c2λ2kv→2 + c3λ3kv→3.

Each eigenvector component evolves by its own factor λik. For these default matrices, the eigenvalue-1 component remains while the other components decay because their eigenvalues have magnitude below 1. Those decaying components describe the adjustment toward equilibrium. Different transition matrices can produce different short-term adjustments as well as different equilibria, so the strongest long-term proposal need not be the strongest at a two-week deadline.

A stationary distribution satisfies Ap→ = p→: after a transition, the expected proportions are unchanged. It does not mean individual vehicles stop changing states; movements into and out of each state can balance.

B. A sensitivity test

A sensitivity test asks how a model's output and the resulting recommendation change when an input or assumption changes. Here, the proposals' transition rates are planning estimates, so we should ask whether our recommendation depends on achieving their full assumed effects.

Compare the original 100%-effect run with a run at 50% for both proposals, keeping the starting fleet, deadline, and readiness target unchanged. This isolates the assumed intervention effect. Assess two questions: does either proposal still meet the 70-vehicle week-2 criterion in expectation, and does the ordering of the proposals change?

The tool interpolates between baseline and proposal:

A(f) = (1 − f)A0 + f Aproposal = A0 + f(Aproposal − A0),   0 ≤ f ≤ 1.

At f = 0, there is no intervention effect; at f = 1, the full proposed matrix applies. At f = 0.5, each transition-rate change from baseline is halved. This does not mean readiness is halved, nor that there is a 50% probability of success. Because the weights are nonnegative and sum to 1, the interpolated matrix still has nonnegative entries and columns summing to 1.

If the target is no longer met or the proposals reverse order, the recommendation is sensitive to this assumption and should be qualified accordingly. If the conclusion persists, it is robust to this particular tested change, not necessarily to every plausible uncertainty.

This is a hypothetical partial-effect scenario, not a confidence interval or a validation of the intervention estimates. In the additional test below, change one assumption at a time and restore the other settings so you can identify what caused a different conclusion.

  1. Compare each proposal's week-2 expected readiness at 100% and 50% effects. Does either still meet the criterion? Is the recommendation or the ordering sensitive to this change? Use the effectiveness plot to estimate whether either proposal crosses the target, and explain what a crossing means under the model.
  2. Choose one additional test: deadline, starting fleet mix totaling 100, or effectiveness. Predict its effect, run it, and record settings and run ID.
